Splitter Windows Test

Test package splitter-0.2.0-fixes-PR1-910df64-windows-x64.zip (built by CI run 40563919244; it still says 0.2.0 inside) · for pull request #1 of github.com/LudaLunizz/Splitter · about 1½ hours plus a long run
How to fill it in: for every row write OK, FAIL or skipped in the right column. On a FAIL, write down what you saw (the exact error text, or a photo of the screen) and carry on with the next row if you can. "Expect" says what should happen.

Before you start

0.1The PC runs Windows 10 version 2004 or later, or Windows 11, 64-bit, with an Intel or AMD processor (Settings › System › About: "x64-based processor"). On an ARM PC, run install.cmd anyway: expect it to stop with "This PC has an ARM processor", change nothing, and end the test there.
0.2Test mode is on. Secure Boot must be off. In an administrator Command Prompt: bcdedit /set testsigning on, then restart. "Test Mode" shows at the bottom right of the desktop. Undo after the test: bcdedit /set testsigning off, restart.
0.3BananaSplit 2.8.6 is installed (github.com/LudaLunizz/BananaSplit/releases).
0.4Write down what Splitter is installed now: none, the released v0.2.0, or 0.1.0 (in Sound settings its cables end in "(Splitter Virtual Cables)").

A. Install

A1If 0.1.0 is installed: unzip the test package and double-click install.cmd. Expect: "Splitter 0.1.0 is installed … run uninstall.cmd" and "Nothing was changed". Then run this package's uninstall.cmd, restart if it asks, and go on with A2.
A2Double-click install.cmd and allow it to make changes. Expect: "Installing Splitter (eleven cables)…" (or "updating its driver" if v0.2.0 was installed), then a list of 22 cables, each ending in "(Splitter Cables)". No red text, in particular not "The property 'Count' cannot be found". If it says a restart is needed, restart and look again.
A3Playback devices (Sound settings › More sound settings › Playback): Splitter 1 to Splitter 6, and Splitter A1 Input, A2, A3, B1, B2 Input: 11 in all.
A4Recording devices: Splitter 1 Output to Splitter 6 Output, and Splitter A1, A2, A3, B1, B2: 11 in all. Splitter A1 to B2 show as microphones.
A5Device Manager › Sound, video and game controllers: one "Splitter Cables", with no yellow warning sign.
A6Run install.cmd a second time. Expect: "Splitter is installed already: updating its driver…", no red text, the same 22 cables, and still only one "Splitter Cables" in Device Manager.

B. BananaSplit

B1Start BananaSplit. The status line does not say "No virtual cables are installed". Menu › Virtual cables… shows Splitter with all eleven cables and none missing.
B2In each channel's menu (strips 1–6, buses A1–B2) the cable can be switched on and off.
B3Strip: play music in a browser with its output set to Splitter 1 (Windows: Settings › Sound › Volume mixer, per app). Strip 1 in BananaSplit shows the level and you hear it clean. Repeat for Splitter 6.
B4Bus: send strip 1 to bus B1. In Windows' Sound Recorder (or Discord) choose the microphone Splitter B1 and record 10 seconds. The recording plays back clean.

C. Sound quality

C1Formats. For Splitter 1 (playback) and Splitter 1 Output (recording), Properties › Advanced: try 16 bit, 24 bit and 32 bit, 48000 Hz, each with B3 again. Each must sound clean: no crackle, no wrong speed or pitch, no silence.
C2Exclusive mode (in the device's Properties › Advanced, "Allow applications to take exclusive control" is on): play into Splitter 1 from a player in WASAPI exclusive mode, e.g. foobar2000 with output "WASAPI (exclusive)". Clean sound in BananaSplit? This is the case the timing fix is for: before it, sound came out garbled.
C3Another recording app: record Splitter 1 Output in Audacity (host "Windows WASAPI") while music plays into Splitter 1, for one minute. Smooth, no gaps or bursts?
C4Delay: click along with a video playing into Splitter 1 while you listen through BananaSplit. Write down if the delay feels larger than a TV that's slightly out of sync (it should be about 30 ms).
C5Long run: leave music playing through Splitter 1 into BananaSplit for at least 1 hour (overnight is better). Afterwards: still clean, no crackle, and the sound hasn't drifted out of sync.

D. Remove

D1Double-click uninstall.cmd. Expect "Splitter is removed." (or "… Restart Windows to finish"; then restart). The Splitter cables are gone from Sound settings and Device Manager.
D2Run install.cmd again, then go over A3, A4 and B1 once more. All 22 cables are back.
D3BananaSplit's other cards and audio devices (speakers, headset, any VB-Audio cables) still work.

E. Optional: Driver Verifier

Only if you are comfortable fixing a PC that blue-screens at startup. Driver Verifier makes Windows stop with a blue screen as soon as the driver does something wrong, which is the point. If Windows won't start any more: boot into Safe Mode (hold Shift while clicking Restart › Troubleshoot › Advanced › Startup Settings) and run verifier /reset.
E1In an administrator Command Prompt: verifier /standard /driver splitter.sys, restart.
E2Repeat A6, B3, B4, C1 and C2, then stop and start playback a few times. No blue screen?
E3Turn it off: verifier /reset, restart.
